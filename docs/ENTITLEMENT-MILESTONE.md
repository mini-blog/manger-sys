## 执行证据

- `pnpm check`：通过，common/api/web类型检查及Prisma schema验证。
- `pnpm test`：7个测试通过，包括新增会员日期与共享枚举检查。现有Qwen适配器测试是mock，不是真实千问调用。
- `pnpm openapi:generate`：通过，新端点与学生DTO同步至common生成类型。
- `pnpm build`：通过；Vite仍有既有vendor分包超过500kB的体积提示，不影响本次构建。
- `pnpm test:entitlements`：通过。启动独立PostgreSQL 17容器，应用5个迁移，运行10组权益集成检查，再seed虚构资料并执行原基础API回归和11组试听流程回归。结束自动删除本次测试容器，不连接项目原数据库。

测试脚本：[隔离运行器](../scripts/test-entitlements.mjs)、[权益集成验证](../packages/api/test/entitlements.mjs)、[会员日期测试](../packages/api/test/membership.test.ts)。集成验证涵盖：同键并发只记一次、不同键允许正常续购、异正文冲突、套餐停用后已成功请求仍可重放、权限先于收据、赠课/购买故障整笔回滚、数据库直接非法写入被拒绝、RepeatableRead跨并发发放保持一致快照。

首次测试发现测试辅助命令返回undefined无法存入收据，已让测试辅助函数返回null后重跑通过。最终核对补齐购课关单的`PURCHASE_RECORDED`原因，并验证重复到课事件不会重开已被购课解决的任务。

## 本阶段的边界

1. 会员分类算法和课时接口已完成；学生分类查询、三Tab、课时列表/弹窗尚未完成。没有添加套餐维护页或支付能力。
2. 新待办原语已在隔离库验证，但旧TeachingService与TasksService尚未整体替换。旧预约仍按单科试听资格，旧反馈尚未写消费流水；人工ENROLLED跟进仍待07b/09d退役。不可把新发放接口与旧预约规则组合成正式业务版本。
3. 测试中的原流程回归明确使用旧规则；正式生历史日期改为直接创建测试夹具，新学生/编辑HTTP不再接受该日期。回归通过不等于权益预约/扣减已验收。
4. 本次只增加兼容扩展迁移，不导入旧学生余额、不根据报名日期伪造购课、不收紧旧Admin任务purpose。旧seed仍是试听演示数据，不作为新权益演示数据；已有预约没有期初流水时，新摘要返回`ENTITLEMENT_DATA_INVALID`，不会静默把负可用量改为0。
5. 下阶段接学生分类查询与页面、权益页面，再按04/06/07接预约占用、到课扣减与跟进；01d/01e负责旧数据核对导入，01f提供权益演示数据，09c完成协调切换后才更新可发布声明。

没有验证真实千问、没有部署生产、没有创建提交或推送远端。
