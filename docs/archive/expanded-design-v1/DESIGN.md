# 学生管理系统 · 设计方案

> 本文定义目标切片；当前仅实现基础工程，完成范围见 [README.md](./README.md)。业务假设待确认，草图附后，工程细节见 [IMPLEMENTATION.md](./IMPLEMENTATION.md)，逐项编码任务和依赖见 [plan/README.md](./plan/README.md)。

## 1. 业务、范围与页面

**目标与用户。** 面向澳洲中小学生家庭的教培机构，以试听获客、购买课时包、持续教学和续费为业务主线。直接用户只有 Admin（顾问／教务）和 Teacher（老师）：前者负责咨询、跟进、排班及课时办理，后者负责授课、出勤和反馈。学生是教学对象，家长／监护人是联系人及可能的付款人，均无本次登录入口；一位家长可关联多个孩子。约千名学生的管理重点是责任明确、下一步不遗漏、安排与课时可追溯。

**完整系统。** 咨询 → 试听 → 跟进 → 家长购买课时包 → Admin 确认收款并发放课时 → 入班、出勤扣课 → 续费或流失。先按线下收款设计，无在线商城。顾问工作台显示低课时提醒（暂定余额 ≤2 单位），学生详情展示订单、流水和入班关系；学生可同时在多个不冲突的班。

**沟通假设。** 不因澳洲定位就假设只用邮箱；原题明确存在微信群。邮箱、电话均为主要联系字段，支持微信，按家长偏好选择渠道：资料与确认适合邮件，临时变更可用短信／电话，试听跟进按偏好处理。记录实际联系对象、渠道和结果；本次只生成草稿、人工沟通后登记，不接入邮件、短信或微信发送。

**目标切片。** Admin 电话或线下咨询，记录科目、年级／待评估级别、多个意愿时间段和联系人 → 筛选周课表预约试听 → Teacher 查看试听置顶名单并记录出勤、反馈 → 原子消耗试听权益、生成负责 Admin 的待办 → Admin 实际沟通后记录结果和下一步。时间偏好可协商，已有安排冲突不可绕过；未填结果进入双方的“待补录”。未联系上、继续考虑、有意购买均保留下一步时间；暂不考虑记录原因并关闭跟进，不自动判定全局流失。

该切片直接解决漏跟进、试听生识别和安排冲突，能展示跨角色协作及服务端规则。“有意购买”仅表示待办理购买，不是成交。课时包、订单、正式入班、付费扣课退款和顾问转交仅设计；首个闭环的班级与初始名单由 seed 提供；目录、账号和菜单管理作为后台配套独立开发。支持 Admin 单次调整未来课次，批量修改每周安排后做。本次不做续费提醒界面、自动排课、补课、消息发送、多校区或家长端，避免挤占闭环验证时间。

| 页面 | 信息与常用操作距离（从角色首页计） |
| --- | --- |
| 登录 | 仅账号、密码和登录按钮；Admin 进入工作台，Teacher 进入自己的课表，支持退出 |
| 顾问工作台 | 我的待办、逾期、今日试听、结果待补录；1 次点击进入跟进表单，或打开建档表单 |
| 学生列表 / 详情 | 搜索与负责人筛选；详情展示联系人邮箱／电话、偏好渠道与语言、课程意向及时间线；从首页进入详情再开预约，2 次点击 |
| 周课表／班级课表 | 周一至周日，约 60 节仅为业务规模；按科目、级别、日期时间、老师及余位筛选，点课次看名单；卡片含预约人数、容量、试听／新生数 |
| 老师课程 | 默认自己的今日课次，可查历史及待补录；名单按试听、新入班、其他排序并配文字标签；打开课次后填写反馈，2 步到表单 |

**管理布局。** 左侧分组菜单、右侧主内容，窄屏使用抽屉。Admin：工作台／待办；教学管理（课表、试听）；资源管理（家长、学生、班级、课程）；系统管理（账号、菜单、操作记录）。Teacher 只有自己的课程和学生，反馈在课次详情内。Admin 能进入所有管理页面，但敏感业务数据仍按负责人授权。菜单只配置已上线页面的名称、排序和显示，不能突破后端角色权限。家长不是员工账号，课程目录不是具体课次。基础学生档案允许先录姓名、年级；进入咨询前补齐主要联系人。账号停用撤销会话，历史关联保留；管理模块逐步实现，不用空页面冒充已完成。

“试听”和“本班首次上课”是独立标签，新生依据本班参与历史判断；试听生置顶并用文字、图标与背景强调。提供 loading、空、错误重试，失败保留输入。业务时区为 `Australia/Melbourne`，日期按 `en-AU` 日／月／年显示；界面暂定英文，草图中文仅用于说明，家长沟通语言独立选择。

## 2. 模型与业务规则

| 实体 | 关键字段与关系 |
| --- | --- |
| User | id、role（ADMIN/TEACHER）、唯一工作 email、passwordHash；员工账号独立于家长联系人 |
| Student | name、yearLevel（可为待评估）、ownerAdminId、status（ACTIVE/ARCHIVED）；一名当前顾问负责多名学生，档案状态与试听、销售意向分开 |
| Contact / StudentContact | name、email、phone、wechatId、preferredChannel、preferredLanguage；studentId、contactId、关系、isPrimary；支持一位联系人关联多个学生 |
| Course / Inquiry | 科目；studentId、courseId、summary、preferredTimeWindows、createdBy/At，保留咨询与时间偏好 |
| ClassGroup / ClassSession | 班级：名称、目标年级／级别；课次：classGroupId、courseId、teacherId、start/end、capacity、status、课堂总结；同班可有不同科目 |
| Enrollment | studentId、classGroupId、startsOn、endsOn（不含）；学生与班级多对多，有效日期确定正式名单 |
| SessionParticipant / TrialBooking | 课次学生名单及 REGULAR/TRIAL 来源，学生+课次唯一；试听另关联 inquiryId、权益、预约状态及操作者 |
| TrialEntitlement / StudentFeedback | 学生+课程试听机会及占用／消耗来源；学生个人到课情况、能力观察、偏好、建议级别、老师和课次时间 |
| FollowUp / FollowUpNote | studentId、唯一来源咨询或试听、dueAt、status、version；追加 contactId、channel（含线下）、沟通结果、备注、操作者与时间 |
| LessonPackage / PurchaseOrder* | 课时包：课程、单位数、AUD 标价；订单：付款联系人、受益学生、商品与成交价快照、支付状态、确认人／时间 |
| Attendance* | studentId、sessionId、result、feedback、chargeStatus；学生+课次唯一 |
| CreditAccount / CreditEntry* | 学生+课程账户；delta、reason、orderId、sessionId、reversesEntryId、createdBy/At、唯一业务键 |

*仅设计，非本次实现。班级与科目解耦，课次及其参与名单是实际安排；试听不创建正式 Enrollment。全班总结不替代每位试听生个人反馈。TrialBooking 状态为 `SCHEDULED → ATTENDED / NO_SHOW / CANCELLED`，终态本次不可修改。FollowUp 为 `OPEN / CLOSED`，到期仅是查询条件；同一来源只建一条，重复沟通追加 Note 并更新到期时间。结果提交或取消与待办创建必须原子完成，初始到期为操作后下一个墨尔本日历日 17:00。

| 强制规则 | 执行层 |
| --- | --- |
| 顾问可看所有学生基础概览，仅负责人能看联系方式、详细历史并修改；老师仅看自己课次的必要教学信息 | NestJS Guard 验证身份，Service 校验对象及返回字段；建档负责人取当前顾问 |
| 至少一位联系人有可用邮箱、电话或微信号；偏好渠道须有对应信息，沟通对象须关联当前学生 | Service 校验；电话支持国际区号，不以手机号或邮箱作为学生唯一标识 |
| 仅可预约尚未开始的有效课次；取消也须在开课前；取消课次不得录结果，其他课次结束后才能录 | Service 校验服务器时间、课次状态、状态转换；到课须反馈，未到课反馈可空 |
| 免费试听每生每课程最多一次到课，最多一条 SCHEDULED；已过期但未录结果仍阻止再约；取消和未到课可约其他课次 | 学生锁内检查；同课次重复预约由数据库唯一约束拦截，不提供取消后同课次重开 |
| 新试听不得与有效正式课次、未取消试听重叠，也不得预约已正式参加的同一课次 | Service 以半开区间 `a.start < b.end && b.start < a.end` 检查；取消课次不参与 |
| 有效课次名单不得超容量，正式名单生成到具体课次后统一检查 | Prisma 事务锁定受影响学生与课次，锁内复查；数据库外键、学生+课次唯一、正容量及 start<end 约束 |
| Admin 仅调整未开始课次的科目、老师、时间；名单仅增减自己负责学生，Teacher 不改排课 | Service 重验学生／老师冲突及级别适配；有试听时先取消或重新确认，禁止静默改科目；操作留审计，历史不覆盖 |
| 结果和跟进重试不可重复创建待办、沟通记录 | 事务、来源唯一约束；结果相同重试返回原值，不同返回 409；跟进使用请求幂等键及 version 防覆盖 |
| 新建或改期的开放待办须设置未来行动时间，关闭须给原因；历史记录不能覆盖 | Service 校验并追加 Note；时间经过后允许逾期，不自动关闭 |

**试听权益。** 按学生＋课程赠送 1 次；预约时剩余 1、可用 0（已占用），到课确认后剩余 0。开课前取消或未到课暂不消耗，释放占用后可重约；结果、消耗记录及个人跟进待办同事务，重试不可重复扣次。待办列明学生、课次日期、科目、授课老师与反馈；不同负责 Admin 分别领取。

课时包可为“100 单位，AUD X”（非真实定价）；订单保留成交价、单位数及适用课程快照，确认收款后以订单唯一业务键发放，防重复充值。权益按学生＋课程归属，暂不支持兄弟姐妹或跨课程共享；标准课暂扣 1 单位，不将课时等同钟表小时，不自动设过期。余额为流水合计；扣费在账户锁内与出勤写入同一事务，余额不足保留出勤、标记待扣。错扣用不可重复的关联冲正恢复，不删原账；现金退款另行确认。

转交时更新负责人、追加转交记录；待办责任随学生当前负责人变化，历史作者不变。替课只影响指定未来课次并检查老师冲突。课次存带时区时间点，按墨尔本当地日期生成每周安排，避免跨夏令时直接加 168 小时；不存在或歧义的当地输入须报错。

## 3. 实现、假设与验收

**架构。** React + TypeScript + MUI + React Query；NestJS 模块化单体 + Prisma + PostgreSQL。NestJS 输出 OpenAPI/Swagger，前端生成类型化 API 客户端；DTO 运行时校验仍在服务端。Cookie 会话登录，写请求校验 CSRF。Docker Compose 编排 web、api、db、一次性 migrate，同源代理、持久化数据库，显式 seed；此规模无需微服务。

**千问。** 基于咨询、历次沟通与老师个人反馈，生成有来源的意向信号、顾虑、待确认问题和下一步建议，再按渠道／语言生成邮件或电话提纲。每项推断关联记录 ID，缺依据输出“信息不足”，不展示未经验证的成交概率、不将能力观察当永久标签。结构化输出并由服务端 Zod 校验字段和来源 ID，10 秒超时／无效输出回退到模板；密钥只在服务端，虚构数据演示。人工审核，不编造承诺、不自动发送或改状态，保存草稿不算完成沟通；验收含真实调用及降级。

**五个优先问题。** 下列未确认项暂按上述规则执行：

1. 顾问间共享哪些信息、转交如何迁移责任；员工及家长常用什么语言和联系渠道？
2. 试听是插班还是独立课，次数按学生还是课程，取消和未到课如何处理？
3. 到课、迟到、请假如何扣费，余额不足是否允许继续上课？
4. 课时包的价格、单位、有效期、退款规则是什么，课程或兄弟姐妹能否共享？
5. 什么事件算正式报名或流失，多久跟进；到期时间是否跳过机构非营业日？暂按日历日，课次以机构安排为准，不自动套用学校假期。

**验收。** Seed 含 3 顾问、4 老师、60 学生及周一至周日约 60 节课及满员、冲突、漏填、逾期待办场景；可用历史课次立即演示结果提交，避免等待新预约下课。用真实 PostgreSQL 和直接 API 调用测试越权、并发抢位、同生冲突、重复请求、非法状态、取消重约、夏令时及 AI 降级。README 给出启动、迁移、seed、账号、测试步骤和尽量部署的地址；说明 AI 工具使用及未采纳建议。设计约 1 小时、工程 1.5、流程 3、AI 1、验证文档部署 1.5–2 小时。

正式开始先 `git init`、建立 public GitHub 仓库并邮件发送链接；初始化到最后提交不超过 10 小时，保留完整历史、不 squash，面试前至少 1 小时提交。交付必须同时包含代码和本设计，设计判断及代码需能独立解释。
